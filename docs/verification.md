# 验证范围

## 此前实机验收

- DeepSeek 语音识别和回复；固定短句触发自定义录音。
- 待机摸头播放本地十句录音，进入 Agent 不再检查更新。
- 傲娇角色回复及表情、摆头联动。
- AI Agent 内同时看到蓝牙转头、张嘴和紫色灯光。
- 调整后，固定录音与较长回复在蓝牙连接时连续播放，用户反馈没有明显卡音。
- 音量控制代码包含设备回读、静音及 NVS 保存；发布时不改变现用音量。

## 独立供电问题的后续确认

用户曾报告拔掉电脑 USB 后触屏无法进入 AI Agent，普通充电头也出现同样现象。当前固件已将主日志控制台改为 UART，USB Serial/JTAG 作为辅助输出，避免 USB 主机断开时日志写入异常影响程序。相关诊断是主机复现和固件构建证据，不等同于最终电池供电实机验收。

用户已于二〇二六年十一月十六日明确测试并确认之前的问题修复，包括独立供电、触摸和按键开机。此结论来自用户实际反馈，不再列为旧版未解决问题。

## 本次 Agent、SD 和电脑控制改动

自动检查覆盖电脑工具权限、断线取消、真实本机 WebSocket 协议、本地录音协商、明确未开始才回退、接收后失败不重复播放、过期与跨连接回执隔离、SD 清单及文件校验、播放租约和解码器互斥。桥接使用假 BLE 检查音量与存储查询共用配置锁、机器人试听实际完成回执、旧固件未知状态，以及电脑状态过期和敏感字段不外传。导入工具使用临时静音素材验证实际 Opus 转换、CRC 和拒绝覆盖。

后续排障中，用户确认摸头及固定场景录音流畅，普通聊天曾出现卡音；音频候选版刷入后，用户确认三十秒故事已经连续流畅。维护页面触摸操作、新版本断开 USB 后物理冷启动仍需单独验收。自动播放排空和状态回读不能代替人的听觉与视觉确认。部署结果与具体检查已记录在发布检查文档中。

本次私有设备已安装 Agent 专用固件，SD 三十一段资源有效，实际静音播放和取消测试通过；电脑助手与新版控制台已安装并在线。云端完成五种实际协议测试，正常打断后可在同一连接继续下一轮。机器人音量已恢复原值。初始化时曾出现一次 SD 容量挂载错误，后续挂载和软件重启正常；新固件物理冷启动仍保留为单独验收项。

后续电脑控制验收发现旧角色提示词仍限制工具只控制表情与姿态。已移除此冲突，并要求每轮新的电脑操作重新调用工具、等待本轮真实结果，不能沿用历史成功回复。用户关闭记事本后，使用同一句打开口令连续两次均成功，电脑助手分别记录了新的成功回执。

## 聊天音频候选版与主分支的区别

候选版仅将音频输出任务优先级由四提高至六，解码仍为五。真实聊天期间输出恢复每秒约十七帧，解码队列未持续积压，采样记录中的收包丢帧计数均为零；用户明确确认声音连续流畅。完整固件构建、九项主机测试及该代码提交的 CI 均通过。

同轮长回答仍出现一次未导致重启的 Task WDT 告警，回溯位于输入任务的 AFE/AEC 处理。与输出优先级调整的因果关系尚未确定，不能据此认定已通过持续稳定性验收。候选版保留在[草稿 PR #1](https://github.com/itknow666/stackchan/pull/1)，当前私有设备运行候选版，主分支尚未包含该调度改动。后续需要持续对话、打断及蓝牙共存测试；不通过关闭看门狗隐藏问题。

没有执行成品发布或生成供他人直接刷写的固件；公开代码不含私人录音。自动检查的结果见仓库 CI；当前这份快照本地执行的结果记录在 `docs/publication-checks.md`。

## Codex 语音任务与场景语音

新增异步任务提交、状态查询和取消。任务必须由电脑助手收到真实请求后启动，启动回执不代表完成。实测发现 Codex 即使无法执行任务也可能正常结束一轮，因此增加严格的最终结果结构：只有正常退出、回合结束、明确报告目标完成三项同时满足，才能进入完成状态；受阻或失败不会选择成功播报。

本次检查通过电脑助手三十五项、桥接十五项、完成通知五项、资源导入与生成工具七项，以及完整 Go 测试、构建和电脑控制与本地录音相关竞态检查。规格、代码质量和语音资源分别审查。

实际 Codex 验证使用桌面应用自带完整执行组件及当前登录目录，在 `workspace-write` 与 Windows `elevated` 后端下执行只读任务：本轮重新读取 README 标题，正确返回项目名，没有修改文件。这不等于 `read-only` 沙箱已通过，本机该模式的读取工具仍被执行策略拦截。账号授权只在本机使用，未传给云服务器。

二十类共二百条新语音已在私人目录生成，含电脑工作、任务通知和互动场景。全部通过有限采样、非静音、时长及语音识别校验，最低识别一致性为零点九三三三；四百个 WAV 与 PCM 文件的哈希已独立核对。总长约七百一十三点五秒。自动检查不能代替逐条人工听感验收。

云端私有录音规则增至二百二十一条，保留原二十一条规则及 SD 包身份；新语音通过清单中的完整调用短语播放。另备四个 SD 导入包，每包五十条新语音及原十条摸头语音，当前设备三十一条 SD 包未替换。Codex 自动提示先使用设备已有的达妮娅录音，详细结果通过任务查询获得。

电脑助手与桥接已安装，连接和原音量回读正常。进一步用本机合成的测试语音经过实际语音识别、模型工具调用和已认证电脑连接，成功提交新的只读检查任务；Codex 重新读取项目标题后返回完成，桥接自动播放现有达妮娅录音，并收到机器人实际播放结束确认。持久通知记录标记为完成；测试客户端未播放云端回复音频，机器人播报走实际 BLE/SD 通道。此结果验证自动链路与设备回执，不等于用户已确认听感；用户亲口派任务和实际听感仍单独记录。本次没有刷新机器人固件，既有音频候选告警继续按独立草稿 PR 跟进。
