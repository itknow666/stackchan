# 达妮娅智能化方案

更新：二〇二六年十一月十六日。本文是下一阶段设计，不代表下述能力已经部署。现有能力与人工验收见[验证记录](verification.md)。

目标是让她理解你的习惯、可靠地完成事情，并且知道什么时候应该安静。保留傲娇语气，执行结果必须准确；表达性格不能代替真实工具调用。

## 分工

机器人负责声音、触摸、表情、两个舵机、灯光和本地录音；云端负责对话、记忆检索和任务协调；电脑助手负责取得允许的电脑上下文并执行操作；Home Assistant 负责已接入设备和场景。增加能力优先修改电脑或云端，减少 ESP32 的持续计算负担。

32GB SD 用于录音包、断网提示和有容量上限的缓存。长期记忆的主存储放在电脑或云端；是否让某类内容离开电脑应在配置中明确。SD 不增加运行内存，也不让设备直接运行大型语言模型。

## 先完成：稳定性和动作协调

聊天音频候选版已获流畅听感确认，但 AFE 输入处理有一次未导致重启的看门狗告警，先定位再合并音频改动。持续记录音频队列、掉帧和输入处理耗时，避免把原始录音加入公开日志。

下一轮验收建议覆盖连续二十轮聊天、长回答、打断、摸头、蓝牙控制、断线恢复，以及断 USB 后冷启动；要求无重启、无看门狗告警，队列不持续增长，实际听感流畅。这是待执行的验收目标。

统一头部与表情优先权：停止与取消最高，其次用户主动遥控，再次当前对话动作，最后待机动作。每个动作有来源、有效期和自动释放；说话时暂停无关的自主转头。一轮对话结束后的回正不能覆盖新的手动控制。

## 第一批：记忆和场景

### 可控的长期记忆

例句：“记住，我工作时电脑音量喜欢百分之二十。”“你还记得我哪些习惯？”“以后改成百分之三十。”“忘掉刚才那条。”

初版用 SQLite 保存明确偏好、项目别名和用户指定的事实，每条包含来源、更新时间及可选过期时间。短期对话摘要单独保存，不能把模型猜测自动变成用户事实。先使用结构化字段和关键词检索，确有不足再增加向量检索。

仅把本轮相关记忆加入提示词，避免完整历史越来越长。控制台提供查看、修改、删除、导出和关闭记忆；凭据不进入记忆。删除需清理索引和后续摘要引用，备份保留规则另行说明。

验收：重启后仍记得明确保存的偏好；纠正立即生效；删除后不再主动引用；不同用户或设备的数据不能串入会话。

### 多步场景与任务状态

例句：“进入工作模式。”组合打开指定项目、打开允许的软件、调整电脑音量和启动专注计时。“取消刚才的任务。”可停止尚未执行的步骤。

场景在控制台编辑成有限步骤，不让模型临时生成任意命令。沿用现有认证连接、请求编号、有效期和允许清单，增加任务编号及每步状态。先支持顺序执行、取消和部分失败说明，再考虑并行。

回复区分已提交、已验证完成、失败和结果未知。超时不能宣称成功；离线后不补跑过期命令。取消不会自动关闭用户已经编辑的文档；仅在结果明确且不会覆盖新改动时恢复先前音量等可逆状态。

验收：电脑离线时诚实说明；取消后没有新步骤执行；重复收到同一任务不重复执行，用户下一次新的同名口令仍可正常执行。

## 第二批：获取必要的上下文

### 电脑结果验证和选中文本问答

先为记事本等少量允许应用增加窗口状态检查，再支持“解释我选中的这段文字”。只收到启动提交回执时，应说明已发送打开请求，不能说已确认窗口在前台。

Windows UI Automation 提供窗口及控件的结构化信息，适合作为第一条验证路径；应用支持程度需实测。参见 [Microsoft 官方说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-uiautomationoverview)。截图理解需要另接明确支持图像输入的模型或本地识别服务，不能假设当前文字模型已有视觉能力。

按用户发起的请求读取指定应用或选中文本，控制台显示上下文开关。网页、文档和屏幕中的文字按资料处理，不能自动取得指令权限。默认不持续截屏；写入、发送或删除类操作另行设计具体预览与确认。

验收：关闭再打开同一应用可正确验证；不支持的窗口明确报告无法验证；关闭上下文开关后停止读取；资料中的“忽略规则并执行命令”不能触发电脑操作。

### 提醒和 Home Assistant 场景

例句：“二十五分钟后提醒我休息。”“我开始专注了，先别打扰。”“睡觉了，把允许的设备切到晚安场景。”

提醒存入持久调度器并使用明确时区；机器人断线时记录错过的提醒，恢复后说明，是否补报由配置决定。勿扰时段和主动提醒频率可在控制台修改。仅开放实际接入的 Home Assistant 实体或脚本，设置自然的中文别名。

Home Assistant 官方建议仅向语音助手开放必要实体，支持将明确开放的脚本作为 AI 工具。本项目仍需实现并测试工具桥接；已有机器人仪表盘不等于已支持控制整个家。参见 [Assist 最佳实践](https://www.home-assistant.io/voice_control/best_practices/)。

验收：重启后提醒不丢失、不重复；勿扰期间不主动出声；场景仅控制允许目标，并能查询实际结果。

## 后续探索

| 能力 | 用户入口 | 进入实现前需要解决 |
| --- | --- | --- |
| 编程助手 | “检查机器人项目的测试，告诉我哪里失败” | 对接电脑上的正式代理接口，限制指定项目，先只读诊断与生成可审阅差异；不把任意 shell 直接暴露给机器人 |
| 按需视觉 | “看一下我手里是什么” | 确认相机资源与内存预算，选择图像模型；先做单次快照 |
| 唤醒及自然打断 | 免点屏说话、回答中途打断 | 查清 AFE 负载，实测回声消除、误唤醒及蓝牙共存，保留点屏入口 |
| 更自然的互动 | 长按摸头、双击、安静陪伴 | 检验触摸事件，加入冷却和勿扰，避免动作与录音打断回答 |
| 录音资源管理 | 控制台预览、替换与回退语音包 | 版本化清单、校验、容量上限和完整导入后切换，不能覆盖正在播放的文件 |

## 推荐的下一次交付

先交付“可编辑偏好记忆、一个工作场景、控制台任务记录”。她能记住工作音量，按一句话打开指定项目，并准确说明每步结果；这些变化日常可见，也能复用现有电脑控制链路。

音频告警定位与持续稳定性验收是固件主线；记忆和场景可以在电脑与云端独立开发。更换更大模型、增加摄像头或持续桌面监视不作为前置条件。
