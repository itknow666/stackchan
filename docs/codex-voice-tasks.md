# Codex 语音任务与完成播报

对达妮娅说“让 Codex……”后，云端使用当前配置的 DeepSeek 整理要求，
电脑在指定工作区创建一条新的、可见的 Codex 桌面聊天并立即开始执行。
每次新请求独立建聊天，不接续旧会话。聊天标题取自语音原话。

新聊天同时显示原始识别文字和整理后的任务，原话优先。整理不会主动增加
禁止联网、只读、禁止修改等用户未提出的限制；需要最新资料的任务仍保留
时效性要求。缺少关键要求时由 Codex 询问。整理失败或输出被截断时不提交。
普通闲聊和直接打开电脑软件不走任务整理流程。

## 桌面模式配置

Windows 电脑必须已登录、Codex 桌面保持运行，电脑助手与云端连接正常。
目标文件夹必须已添加为 Codex 项目。参考
examples/pc-assistant.codex-desktop.example.json，合并到现有私有配置，
保留真实的连接地址、独立令牌、应用列表等设置。

codex.backend 设为 desktop。配置项：

- desktop_workspace：固定的本机工作区绝对路径。
- desktop_node：本机 Node 可执行程序绝对路径。
- desktop_server：Codex 自带 codex-app-tools 插件的 server.mjs 路径。
- desktop_caller_thread：明确授权语音通道的现有聊天编号，用作官方 MCP
  调用上下文，不是新任务的目标聊天。
- tasks_file：私有任务记录，保存状态、摘要及返回的桌面聊天编号。

示例为模拟模式，配置完整后启用真实执行。桥接使用桌面自带的官方 MCP
服务与标准 stdio 协议，重新连接时发现当前桌面管道，不写死管道编号。
没有桌面实例、同时发现多个实例、工作区未注册或插件不兼容时报告失败，
不会退回隐藏 CLI。插件升级若安装路径变化，需要更新本地配置。
这是已在本机验证的插件接入，仍依赖该插件版本及提供的工具。

桌面模式沿用用户的模型、权限和项目设置，不指定模型，不改全局配置，
不强制跳过批准。文件访问范围由 Codex 当前权限决定；工作目录不是
沙箱边界。旧 CLI 配置中的 sandbox、windows_sandbox、timeout_seconds
不控制桌面任务。

新建成功返回 task_id 与 thread_id，接收不代表做完。最多观察四条进行中
任务。提交超时或结果未知时不重试，应先查看桌面，防止重复建任务。
助手重启后继续观察已创建聊天，不重新提交，不关闭用户的 Codex。
桌面任务没有由电脑助手强制施加的执行时限。

“查询 Codex 最新任务”可读取摘要。当前桌面工具没有远程停止接口，
停止请求会如实提示到对应聊天点停止，不会假称取消成功。
停止不会撤销已发生的修改。

正式轮次结束后，最终答复明确以“任务完成”开头才发送成功通知。
需要补充信息、失败或无法确认的结果不发送成功通知。这仍是模型报告，
不代表用户已验收；需查看实际测试及限制。

## 机器人完成提醒

保留现有 Home Assistant 的 pc_assistant 和 codex_notifications 设置。
PC 状态须在十五秒内更新、真实在线，机器人 BLE 已连接且可播放。
USB 充电不等于 BLE 连接。成功使用已安装的 SD 录音 done，
失败或未确认使用相应配置录音；不直接念出可能含私密信息的完整结果。
详细结果可在桌面聊天查看，或向达妮娅查询。

通知去重在物理命令前持久化。断开、超时或播放结果未知不会重放；
仅设备明确返回开始前不可用时，在完成后两分钟内等待待机重试。
状态投影不含原始提示词、摘要、路径或凭据。私有任务记录和配置不能
提交到公开仓库。

## 旧 CLI 模式

未配置 backend 时保留 cli 模式，供未接入桌面插件的安装使用。
该模式为后台 CLI 会话，不创建可见桌面聊天；原有项目允许列表、
沙箱、超时、进程树清理和结构化结果校验仍适用。
本机语音通道已配置为 desktop，不会自动切换到 CLI。

## 验证

单元测试不启动真实 Codex：

```powershell
$env:PYTHONPATH='pc-assistant'
python -m unittest discover -s pc-assistant/tests
```

真实验收可说：“让 Codex 在测试profile新开任务，只读取当前工作目录名称和
路径，不要修改文件。”检查左侧新聊天、工作区路径、原话和整理指令，
再检查完成通知。第二次同样要求应生成另一条新聊天。

真实任务使用当前登录账号的正常额度。本功能不监控或兑换额度。
